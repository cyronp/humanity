# Decisions

Decisions that the spec does not cover. Entries marked **confirmed** were answered by the human; entries marked **needs confirmation** were decided conservatively by the agent while building and should be reviewed.

## Confirmed by the human

- **2026-11-09 — How to handle uncovered decisions.** Decide conservatively, log here as "needs confirmation", list them in the hand-off. Only stop for choices that are expensive to reverse.
- **2026-11-09 — `settingSources`.** Agent sessions load `["project"]` only: the repository's `CLAUDE.md`, `.claude/skills` and `.claude/settings.json`. User-level (`~/.claude`) skills, MCP servers and hooks are not loaded.
- **2026-11-09 — `NotebookEdit`.** Its policy mode stays `review`, but because a notebook change cannot be safely simulated as text hunks, any `review` tool without a simulator falls back to the Allow / Deny confirmation card showing the full input.
- **2026-11-10 — The agent runs on the human's Claude subscription.** Asked for explicitly by the human, following how T3 Code (`pingdotgg/t3code`) connects. Humanity holds no Anthropic credential: it runs Claude Code through the Agent SDK, and Claude Code signs in with whatever login lives in its config directory (`claude auth login`, a Claude Pro/Max/Team/Enterprise account). This replaces the spec's "`ANTHROPIC_API_KEY` is read from the environment": a key there still works, because Claude Code honours it, but it is no longer the intended path. A first-run guide at `/welcome` explains this and shows the connected account.

## Needs confirmation

- **M1 — Token transport.** The token is sent as `?token=` on the WebSocket URL (browsers cannot set WebSocket headers) and as `Authorization: Bearer` on `/api/auth`. The web app moves it from the page URL into `localStorage` on first load.
- **M1 — Extra endpoint `/api/auth`.** Not in the spec. Added so the UI can show "wrong token" and "daemon not running" as different, actionable states.
- **M1 — Default policy details.** Besides `Read`/`Glob`/`Grep`, `TodoWrite` and `Skill` default to `auto` (neither touches the worktree's files; a Skill's own tool calls are still gated). `NotebookEdit` defaults to `review`, `WebFetch`/`WebSearch`/`Bash`/`mcp__*` to `confirm`. Everything else, including `Agent`, falls back to `confirm`.
- **M1 — Policy shape.** A policy is an ordered list of `{ pattern, mode }` rules. A pattern is an exact tool name or a prefix wildcard ending in `*`. Exact beats wildcard, longer wildcard beats shorter.
- **M1 — `addLocal` path.** A path inside a repository is resolved to the repository root (`git rev-parse --show-toplevel`). The same root cannot be added twice.
- **M1 — shadcn/ui setup.** Generated with the official CLI (`shadcn@4.23.0`, base `radix`, preset `nova`). The CLI added three packages that the spec does not list: `cn` (shadcn's class merger, replacing `clsx` + `tailwind-merge`), `shadcn` (its Tailwind stylesheet) and `@fontsource-variable/geist` (the preset's font). All pinned exactly.
- **M1 — "Live layer and test layer" per service.** Services whose test double adds value get one (`AgentRunner`, `GitHubService` through a mocked `HttpClient`, the database through `DatabaseTest`). `GitService` and `ProjectService` are tested through their live layers against temp repositories and a temp data directory, as the spec's testing section asks.
- **M2 — What `Git.diff` shows.** The working tree against `HEAD`, plus untracked files synthesized as all-additions hunks (git's own diff omits them). Untracked files over 512 KB or containing NUL bytes are listed without content.
- **M2 — No checkout RPC.** `GitService.checkout` exists and is tested inside worktrees, but no RPC exposes it for the user's repository, because that would modify the user's working copy. "Switch branch from the UI" is implemented as choosing the base branch for a new session.
- **M2 — `Git.createBranch` only creates a ref** in the project's repository (`git branch -- <name> <from>`); nothing is checked out.
- **M2 — CRLF handling in the `Edit` simulator.** Matching is done on LF-normalized text and the file's CRLF endings are restored, mirroring how the model sees files. `Write` is simulated with the content exactly as given.
- **M2 — A no-op change is denied, not allowed.** When a simulated `Edit`/`Write` produces content identical to the file, there is nothing to review; the tool call is denied with an explanatory message rather than allowed to touch the file unreviewed.
- **M3 — SDK state inside the data directory.** _Superseded on 2026-11-10 by "The agent runs on the human's Claude subscription": sessions now use Claude Code's own config directory, where the login lives._ The SDK runs with `CLAUDE_CONFIG_DIR=<home>/claude`, so its transcripts (needed for resume) are written inside `~/.humanity`, per the "never write outside" rule. Side effect: credentials from a `claude` login in `~/.claude` are not used; `ANTHROPIC_API_KEY` from the environment is required, as the spec says.
- **M3 — One agent process per session, kept while the daemon runs.** A session's process starts on its first message and stays open between turns (streaming input mode), until the session ends, its project is removed, the process fails, or the daemon stops. The next message after any of those resumes with the stored SDK session id.
- **M3 — Status semantics.** `running` while a turn is in flight; `idle` after a successful turn; `error` (with the reason) when a turn ends in error or the process fails, and sending a new message is still allowed; `interrupted` after an interrupt or a daemon restart; `ended` is final.
- **M3 — System prompt.** The SDK's `claude_code` preset plus a short append telling the agent that changes are reviewed hunk by hunk and that denials carry the human's feedback.
- **M3 — What is persisted.** Every SDK message except streaming partials (`stream_event`) and the SDK's echoes of prompts Humanity already recorded. Unrendered types are stored as `other` with their raw JSON.
- **M3 — Subagent output** (messages with a `parent_tool_use_id`) is shown indented in the chat for now; M5's renderers can nest it under its tool call.
- **M3 — `PowerShell` defaults to `confirm`.** The CLI exposes it next to `Bash`. Other tools it exposes (`Task`, `EnterWorktree`, `Cron*`, `Monitor`, ...) are not listed and fall back to `confirm`.
- **M3 — Streamdown code highlighting** uses a small code plugin over Humanity's own Shiki highlighter instead of the `@streamdown/code` package, so chat and diffs share one Shiki instance and theme wiring and no dependency is added.
- **M4 — A file changed during review is never partly overwritten.** Before writing approved hunks the daemon checks the file still has the content the hunks were computed from. If it doesn't, nothing is written, the change is recorded as `rejected`, and the agent is told to re-read the file.
- **M4 — Interrupted requests are `expired`.** The spec reserves `expired` for daemon restarts; it is also used for requests released by an interrupt or by ending the session, since in every case the request can no longer be answered.
- **M4 — Paths outside the worktree are denied without asking.** An `Edit`/`Write` whose `file_path` resolves outside the session worktree is denied immediately with an explanation, never shown for review.
- **M4 — Denial wording.** Confirmation denials read `DENIED by the human reviewer: <comment>`, or a default asking the agent not to run the call and to ask how to proceed. Simulation failures and no-op edits start with `NOT APPLIED:` so the agent can tell them from a human's rejection.
- **M4 — "Always allow" sets the exact tool name to `auto`.** For MCP tools that is the full `mcp__<server>__<tool>` name, not the whole server.
- **M4 — Keyboard model.** Shortcuts act on the focused hunk across all pending changes; `Enter` submits the change that hunk belongs to and only works once every hunk of it has a verdict. Inside a comment field, `Escape` leaves the field and `Ctrl+Enter` submits.
- **M4 — Review panel placement.** On wide screens the panel takes the right ~55% next to the chat; on narrow screens it replaces the chat while open. It opens by itself whenever a new change arrives.
- **M5 — No ANSI library.** Bash output colours are handled by a ~90-line parser in `features/tools/ansi.ts`. Standard and bright foreground colours, bold, dim and underline are kept; other escape sequences are dropped.
- **M5 — Subagents get a renderer.** `Task`/`Agent` calls show the subagent type, task and final report. Their inner messages remain indented in the chat rather than nested inside the card.
- **M5 — Edit/Write without a review** (only possible if a project sets them to `auto`) show a diff of `old_string` → `new_string` or the written content, labelled as a snippet, since the original file is not known to the UI.
- **M6 — Token handling for git.** Clones pass the token as `http.https://github.com/.extraheader` through `GIT_CONFIG_COUNT/KEY/VALUE` environment variables of that single process. It never appears on the command line or in the clone's `.git/config`. As a consequence, later `git fetch` in a clone has no credentials; there is no push or fetch in the MVP.
- **M6 — `listRepos` returns an array, capped at 1000.** The service exposes the paginated `Stream`; the RPC collects it, so the UI can filter locally.
- **M6 — Public repositories without a token.** `getRepo` and `listBranches` work unauthenticated for public repositories, so "clone by name" works even when no token is configured. Listing "your repositories" requires a token.
- **M6 — Existing folders are never overwritten.** If `<home>/repos/<owner>/<repo>` exists (for example after removing its project), cloning stops with `CloneTargetExists`; the human removes the folder or adds it as a local project.
- **M6 — "Switch project and branch".** Projects are switched by navigating between them. Branches are "switched" by starting a session from a branch (local or `origin/*`); nothing ever checks out a branch in the user's own working copy.
- **M7 — Commits include everything in the worktree.** `Sessions.commit` stages all changes in the session worktree (`git add --all`), which are the hunks the human approved plus anything the human edited there by hand. The Changes tab shows exactly that diff before committing.
- **M7 — No commits mid-turn.** Committing is refused while the session is `running` or `waiting_for_human`.
- **M7 — No HTTP request log.** The default per-request log printed full URLs, including `?token=` on the RPC socket, so it is disabled.
- **M7 — Pull requests not implemented.** Listed as a nice-to-have; it would need write access on the token and a push, which the MVP otherwise avoids.
- **Claude connection — `ANTHROPIC_API_KEY` is passed through, not stripped.** Same as T3 Code. Claude Code prefers an API key over a subscription login, so when both exist the key is billed. Humanity detects this (`apiKeySource` next to a `tokenSource`) and shows a warning in the header badge, the guide and the daemon banner, with the fix (unset it, restart). Stripping the key instead would be a one-line change in `claudeEnvironment`.
- **Claude connection — the bundled CLI.** Sessions and the account check use the Claude Code executable that ships with the Agent SDK (its platform package), not a `claude` on PATH. T3 Code uses the PATH binary with a configurable path. Bundled means no separate install and no Windows `.cmd` shim problems; it reads the same login. The guide offers the bundled CLI's own `auth login` command for people without a global `claude`.
- **Claude connection — how the account is checked.** Like T3 Code: start `query()` with a prompt that never yields, read `initializationResult()` (`account`, `claude_code_version`), close. No message is sent to Anthropic. The check runs with `settingSources: []`, no tools and no MCP servers, in `~/.humanity`. A connected result is cached for 5 minutes, anything else for 10 seconds; `Claude.status { refresh: true }` forces a new check. The connection step polls every 5 seconds while signed out, so a fresh login shows up by itself.
- **Claude connection — inherited session variables are removed.** `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_ENTRYPOINT` and the other variables a parent Claude Code session sets are dropped from the CLI's environment, so a daemon started from inside Claude Code does not spawn "nested" sessions. `CLAUDE_CONFIG_DIR` is kept.
- **Claude connection — no in-app sign-in button.** The guide asks the human to run `claude auth login` in a terminal (what T3 Code does too) instead of the daemon spawning the login flow, which opens a browser and may need a TTY. Possible follow-up.
- **Onboarding — completion is per browser.** Stored in `localStorage` (`humanity.onboarding.completed`). The first visit to `/` redirects to `/welcome`; the header's Claude badge and help button reopen it.
- **Onboarding — Claude icon.** Served from `apps/web/public/claude.svg`. That file was not in the repository yet; until it is added, `ClaudeMark` shows a neutral sparkle in Claude's accent colour.
- **Merge of M3–M7 with the Claude connection (2026-11-10).** The two lines of work were developed separately from M2 and merged. The agent runner now starts Claude Code with the same cleaned environment as the account check (`ClaudeCode.environment`) instead of `CLAUDE_CONFIG_DIR=<home>/claude`, so sessions run on the human's login. Claude Code's transcripts therefore live in its own config directory (`~/.claude` or `CLAUDE_CONFIG_DIR`), which Claude Code writes, not Humanity. Sessions created before the merge kept their transcripts in `~/.humanity/claude` and cannot be resumed with full history. The daemon no longer warns when `ANTHROPIC_API_KEY` is missing; the Claude account line replaces it.
- **Dev — turbo passes the daemon's environment through.** Turbo 2's strict env mode dropped `ANTHROPIC_*`, `CLAUDE_CONFIG_DIR`, `GITHUB_TOKEN` and `HUMANITY_*` from `npm run dev`. The `dev` task now lists them in `passThroughEnv` (it is uncached, so they affect no cache key).
- **Companion pivot dropped (2026-11-10).** The human chose to keep the Agent SDK architecture with the subscription login over the Claude Code companion pivot. The pivot document and its hooks proof of concept are not part of the repository.
- **shadcn AI Elements in the web app (2026-11-10, needs confirmation).** The chat uses shadcn's AI components, added with the shadcn CLI (radix-nova style): Message Scroller (transcript scrolling, replaces the manual scroll-to-bottom effect), Message + Bubble (turns), Trace (tool call lines that shimmer while running, collapsed thinking, turn and init lines), Code Block (tool output, JSON, terminal output, Bash confirmations, with copy buttons), Input Group (composer) and Item (confirmation card). Only the presentational components are used; nothing from the Vercel AI SDK (`ai`, `@ai-sdk/react`) was added, because the agent is the Claude Agent SDK. New dependency: `@shadcn/react` (pinned at 0.3.1), which Message Scroller needs. The registry's `lib/highlighter.tsx` and `hooks/use-highlighted-code.ts` were removed: Code Block is fed by Humanity's existing Shiki instance, so chat, tools and diffs keep one highlighter. The review panel's hunk view is unchanged; it stays Humanity's own component.
- **Chat-first layout (2026-11-10, needs confirmation).** `/` is now a chat page: one message box that starts a session (branch + worktree) in the last prompted project, with pickers for the project and base branch. "Last prompted" is the project of the most recently active session (`updatedAt`), so it follows the daemon, not one browser. The project list and the add/clone forms moved to `/projects`; `/projects/$projectId` and the session workspace are unchanged. The setup guide (`/welcome`) has no sidebar.
- **Sidebar of conversations (needs confirmation).** shadcn's Sidebar lists every session that is not `ended`, across all projects, most recently active first. Each row: project favicon (or a coloured initial), project name, time in the current state; the session title; the branch and the provider's icon. Running and waiting-for-you rows show a pulsing dot (green, amber) and tick every second; others every 30 seconds. The time counts from `updatedAt`, which the daemon sets on every status change; a `waiting_for_human` → `running` resume therefore restarts the running time. No new column.
- **`Sessions.watchAll`.** A new streaming RPC sends all sessions on subscribe and again after any session is created, changes status, or is removed with its project. `SessionEvents` has one shared "list changed" signal (a sliding PubSub of size 1, so bursts collapse) next to the per-session hubs.
- **`Projects.icon` reads the user's repository (read-only).** The daemon looks for `favicon`/`icon`/`logo` `.svg|.png|.ico` in the repository root and the usual web folders (`public`, `static`, `app`, `src/app`, `src`, `assets`), then in `apps/*` and `packages/*` (web-like names first). Files over 256 KB, non-files and symlinks leading outside the repository are skipped. The icon is sent inline as base64 and shown with `<img>`, so an SVG cannot run scripts.
- **Providers.** `features/providers/ProviderIcon.tsx` maps a provider id to its name and real icon. Only `claude-code` exists; every session is shown as Claude Code (no provider column yet). The Claude mark is Simple Icons' `claude` path (CC0) in Claude's brand colour; `ClaudeMark` now uses it, replacing the missing `public/claude.svg` fallback.
- **Turn cost hidden.** The end-of-turn line no longer shows `costUsd`: it is an API-price estimate even on a subscription and read as a charge. It is still stored.
- **One app header (2026-11-10, needs confirmation).** Every page inside the app layout shows the same transparent header: content scrolls under it through a progressive blur (five backdrop-blur layers with staggered masks, plus a fading tint). Pages fill it through a portal (`<AppHeader>`) and leave `pt-14` of room at their top. Breadcrumb: `project ▾ / page`. Picking a project in the dropdown opens a new thread in it (`/?project=<id>`, shared with the composer's project picker); the dropdown also links to the project's settings page and to the project list. The project page's "← Projects" link was removed in favour of it.
- **Header contents in a thread.** Only the breadcrumb, the Review toggle and Interrupt (while the agent works). The status badge, branch, worktree path and End button were removed: status shows as the row's dot and time in the sidebar, the branch on the row, and End moved to the row. That "waiting for you" is still obvious relies on the sidebar's amber dot, the Review button's count, the pinned confirmation cards and the tab title.
- **Ending a session from the sidebar.** The End button (with its confirmation dialog) takes the place of the row's time on hover or keyboard focus. On touch screens, which have no hover, the button is always shown and the time is hidden.
- **Sidebar toggle.** It sits in the sidebar's header. When the sidebar is collapsed, or on a phone where it is a slide-out sheet, the app header shows a toggle too, since there is otherwise no way to bring it back.
- **Sessions remember their model.** Migration `0002_session_model` adds a nullable `sessions.model` (`NULL` = Claude Code's default, which is what every earlier session gets). Resumes after a daemon restart run on the same model. The model is not validated by Humanity: an unknown value fails in Claude Code and surfaces as the session's error. Changing the model of an existing thread is not offered yet.
